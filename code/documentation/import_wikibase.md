# Wikibase import pipeline

## Purpose

`import_wikibase.ipynb` populates a Wikibase instance with the entities comprising the European Fishing Fleet Knowledge Graph (EFFKG).

The notebook supports modular execution and can independently perform the following stages:

- Wikibase property creation;
- creation of optional base vocabulary entities;
- import and update of Spanish port entities;
- import of annual vessel-count statistics by port;
- import and update of vessel entities.

Each stage is controlled independently through the corresponding `RUN_*` configuration flag.

---

# Repository requirements

The notebook must be executed from the root of the EFFKG repository.

The following repository structure is expected:

```text
code/
dataset/
schema/
source_data/
data_model/
validation/
documentation/
```

The repository root is detected automatically during execution. All input, output, checkpoint and log paths are resolved relative to this directory.

# Software requirements

The notebook requires:

- Python 3.9 or newer;
- the packages listed in `requirements.txt`;
- access to a Wikibase instance compatible with the EFFKG data model;
- a Wikibase account with permission to create and update entities.

Create a `.env` file in the repository root containing:


These credentials are required for both normal execution and dry-run mode because the notebook queries the target Wikibase to resolve existing entities and compare generated statements.

# Execution modes

Two import modes are available.

## European fleet only

```python
INPUT_MODE="eu_only"
```

Imports data derived exclusively from the European Fleet Register.

---

## Consolidated national and European data

```python
INPUT_MODE="national_eu"
```

Imports the consolidated datasets combining European and Spanish national information.

# Execution stages

Each processing stage is enabled independently.

| Flag | Stage |
|------|-------|
| `RUN_PROPERTIES` | Create Wikibase properties |
| `RUN_BASE_ITEMS` | Create optional controlled entities |
| `RUN_PORTS` | Create or update Spanish ports |
| `RUN_PORT_STATS` | Import annual port statistics |
| `RUN_VESSELS` | Import vessel entities |

Multiple stages may be executed during the same run.

---

# Dry-run mode

Setting

```python
DRY_RUN=True
```

evaluates every enabled execution stage without modifying Wikibase.

Depending on the enabled stages, the dry run reports:

- properties that would be created;
- base entities that would be created;
- ports that would be created or updated;
- annual statistics that would be replaced;
- vessels that would be created;
- vessels that would be updated;
- vessels whose generated statements already match the existing graph;
- unresolved registration ports;
- processing errors.

A structured execution report is written to:

```text
validation/reports/
```

Dry-run execution is recommended before large imports or updates.

---

# Checkpoint mechanism

The vessel-import stage records execution progress in a JSON checkpoint.

Each checkpoint stores:

- processed files;
- last processed row;
- last processed CFR identifier;
- created entities;
- updated entities;
- processing errors;
- completion status.

Interrupted executions can therefore resume without restarting previously completed files.

---

# Statement-level provenance

All imported statements include statement-level references.

Reference values correspond to the canonical source-resource URLs documented in:

```text
documentation/data_dictionary/reference_sources.csv
```

That file provides the complete provenance information associated with every reference identifier, including:

- source resource;
- provider;
- version or snapshot;
- licence or reuse conditions;
- retrieval information.

Together, the Wikibase references and the accompanying documentation allow each imported statement to be traced back to its original source resource.
